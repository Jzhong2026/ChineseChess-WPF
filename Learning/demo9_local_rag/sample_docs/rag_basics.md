# RAG 基础

RAG 是 Retrieval-Augmented Generation 的缩写，意思是检索增强生成。它的核心思想不是让大模型提前记住所有资料，而是在回答问题之前，先从外部知识库检索相关内容，再把这些内容作为上下文交给模型。

一个常见 RAG 流程包括五步：

1. 文档读取：加载 Markdown、PDF、代码或数据库内容。
2. 文档切分：把长文档切成较小的 chunk。
3. 建立索引：用关键词索引或向量索引保存 chunk。
4. 问题检索：根据用户问题召回最相关的 chunk。
5. 生成回答：把问题和上下文放进 prompt，让模型基于资料回答。

RAG 的优势是资料可以随时更新，回答也能给出引用来源。它的风险是检索不到正确资料时，模型可能仍然生成看似合理但不可靠的回答，所以应用层应该提示资料不足。

## Chunk 设计

chunk 太大会让上下文变得嘈杂，chunk 太小又容易丢失完整语义。常见做法是设置固定长度，并在相邻 chunk 之间保留 overlap。

## 引用来源

面向用户的 RAG 产品应该展示来源文件、标题、片段或链接。这样用户可以判断回答是否可信，也方便排查错误检索。
