# 中国象棋单机版 — 棋力测试与提升方案

## TL;DR

- **qsearch+tt(经典) 横扫 MCTS+NN:三组测试 12 局 Classic 全胜 0 负**
- 主要不是搜索算法弱,而是 **NN 模型本身没学会下棋**(val_acc ≈ 5%)
- **TT 命中率仅 2-5%**,置换表几乎没起作用 — 经典搜索的实现也有改进空间
- 短期最容易见效:**修 NN 训练 + 经典搜索加 null-move/LMR/hist + 评估函数补 mobility**
- 中期:MCTS 上 GPU/batch 推理 + 重新训练更大数据量的策略-价值网络

## 3. 关键诊断 — 哪里出了问题

### 3.1 NN 模型几乎没学到东西(致命)

查看 `artifacts/training_v7.log`:

```
epoch=001  train_loss=4.80  train_acc=0.0446  val_acc=0.0435  val_top10=0.3206
epoch=005  train_loss=3.43  train_acc=0.0596  val_acc=0.0458  val_top10=0.3384
epoch=010  train_loss=2.85  train_acc=0.0876  val_acc=0.0474  val_top10=0.3372
```

- **val_acc 最高 5.0%**(8 选 1 的策略准确率,纯随机也 12.5% — 实际比随机还差!)
- val_top10 ≈ 34%,说明即使给 10 个候选着,真正正确的也不在里面的概率是 66%
- 训练样本只有 **74k**,而模型有 **6.32M 参数** — 严重过拟合风险 + 数据量不足
- `train_loss` 还在 2.85 还在快速下降,说明模型根本没收敛

**直接影响**:
- 纯 NN 策略 4 局,平均 10-47 步就被杀 — **因为根本不知道哪步是好棋**
- MCTS 拿到一个噪声先验,搜索只是在噪声里挑稍好的 — 救不回来

### 3.2 MCTS 模拟数严重不足

- 设定 3000 sims,**实测只跑到 1100-1200 sims/步**
- 原因:每次模拟都做一次完整 NN 推理(CPU),单次推理 ~4ms,5000ms ÷ 4ms ≈ 1250 sims
- **PNet 推理是 MCTS 的最大瓶颈**

### 3.3 TT 命中率异常低(2-5 %)

正常 Alpha-Beta 在迭代加深 + transposition table 下,TT 命中率应该有 **30-50 %**。但这里只有 **2-5 %**。

排查 `XiangqiAiService.cs`:

1. **置换表只存 bestMove,没存 score**(`TranspositionEntry` 只有一个 `(int Depth, Move? BestMove)`)
   - 这意味着即使命中了 TT,也只能用作 move ordering,**不能用 cut-off**
   - 实际等于没用上 TT 的核心价值

2. **`MaxTranspositionEntries = 250k`,但每次迭代开始前 `_transpositionTable.Clear()`**
   - 每个 root 步都从零开始建表,迭代内只能复用当前搜索树内的命中
   - 浅搜索(3-4 层) + 简单迭代加深,跨兄弟节点的重用极少

3. **Score reuse 被显式禁用**(代码注释 "Score reuse is disabled until repetition/history state is included in TT key")
   - 杀禁着规则依赖历史,所以 hash 必须包含历史,否则不能截断 — 这是合理的工程取舍
   - 但代价是 TT 命中率直接腰斩

### 3.4 经典搜索浅,迭代加深到不了 8 层

- 配置 Level 4 = 8 层,**实际平均只到 3.6 层**
- 5 s 时间预算 + 每次节点扩展都要 GetLegalMoves + ApplyMove(全是 C# 对象分配),5 s 内只搜 ~25k 节点
- QSearch 触发条件是 `depth == 0`,但只搜吃子,没搜将军/逃将,容易漏杀

### 3.5 评估函数过于简单

```csharp
PieceValues = { General=10000, Rook=900, Cannon=450, Horse=400, Elephant=200, Advisor=200, Soldier=120 }
PositionalBonus = { Soldier: forward*14 - centerDist*3; Horse: 25 - centerDist*4 - rowDist*2; ... }
+ IsInCheck ±35-45
```

- **缺**:子力机动性(mobility)、将帅安全(king safety)、兵形/车形控制、要塞/牵制、空间优势
- 只看子力 + 粗略位置,导致开局/中盘局面判断力有限
- 但在 NN 模型完全瞎猜的对比下,这个简单评估就足以碾压了

## 4. 提升方案(按优先级)

### 4.1 必做 — 重新训练 NN(影响最大)

| 问题 | 改进 |
|---|---|
| 样本量 74k 对 6.3M 参数严重不足 | 扩到 **500k+** 自对弈样本(用当前 MCTS 自对弈,即使弱也比瞎走好) |
| Train/val loss 还没收敛 | 至少训练 **50-100 epoch** 到 val_acc > 30% |
| `train_loss=2.85` 还在快速下降 | 检查学习率调度 — 当前 `9.8e-5` 可能太小了,改用 cosine decay |
| 样本质量可能差 | SelfPlay 时 MCTS 用 **800+ sims**(即使弱也比 policy 抽样稳),temperature decay,过滤 5 步内决出的垃圾对局 |
| Value head 训练不稳 | 训练数据中明确 `result ∈ {-1, 0, 1}`,value 用 Huber loss 而不是 MSE |

**目标**:val_acc > 30%,value pred 与真实结果相关系数 > 0.5。达到这个水平,MCTS 应该立刻比 Classic 强。

### 4.2 短期 — 修经典搜索的实现

**a) TT 加 score + cutoff(高 ROI)**

```csharp
record TranspositionEntry(int Depth, double Score, byte Flag, Move? BestMove);
// Flag: EXACT / LOWER_BOUND / UPPER_BOUND
```

加上 score 复用后,即使保持 250k 表 + 每次 clear,TT 命中率能从 3% 提到 20%+,**搜索深度可以多 1-2 层**。

**b) Move ordering 加 history + killer moves**

当前只用了 MVV-LVA + TT best move。补上:
- `killerMoves[depth][2]` — 每个深度保留最近 2 个引发 cut-off 的 quiet move
- `historyTable[from][to]` — 累计引发 cut-off 的分数,跨深度复用

这两项在象棋里能砍掉 **30-50% 节点**。

**c) 加 LMR / null move pruning**

```csharp
// Null-move pruning: 跳过自己一步,如果对手还是 >= beta 就截断
if (depth >= 3 && !inCheck && hasNonPawnMaterial)
{
    var score = -Search(swapSide, depth - 3, -beta, -beta + 1);
    if (score >= beta) return beta;
}

// Late move reduction: 后面的 quiet move 搜浅一点
if (moveIndex >= 3 && move.IsQuiet && depth >= 2)
{
    var score = -Search(nextBoard, depth - 2, ...);
    if (score < alpha) continue;
}
```

预期 **节点数砍 50%**,搜索深度能多 1-2 层。

**d) QSearch 扩展为 "tactical search"**

当前只搜吃子。补上:
- 将军逃将(应对威胁)
- 升变(象棋无升变,跳过)
- 牵制/解除牵制的关键子

这样残局 + 中盘战术不会漏。

### 4.3 中期 — 评估函数增强

| 项 | 收益 |
|---|---|
| **Mobility**:每多一个合法走法 +0.5 分 | 中盘判断显著提升 |
| **King safety**:九宫内是否有士象完整保护 | 残局/攻杀关键 |
| **Pawn structure**:兵林/过河兵加分 | 残局判断 |
| **Rook on open file**:车在开放线 +20 | 中局常用评估 |
| **Bishop/Cannon pin**:马腿/象眼被堵 -10 | 战术捕捉 |
| **Tempo + repetition awareness**:重复局面奖励和棋 | 减少送子 |

### 4.4 中期 — MCTS 性能优化

- **GPU 推理**:ONNX Runtime CUDA / DirectML provider,5 s 应该能跑 5000-10000 sims
- **Batch 推理**:叶子节点攒 8-16 个一起送 NN,推理延迟摊薄
- **Virtual loss**:并行模拟时给选中节点加虚拟损失,避免多线程撞同一支
- **Tree reuse**:复用上一手搜索的子树(对手走了一步,大部分子树可复用)

### 4.5 长期 — 架构升级

- **NN 架构**:试 ResNet-20 + squeeze-excitation,目标 8-12M 参数 + 强数据
- **两阶段训练**:先用 SL(supervised learning)从大师对局学 policy,再 RL fine-tune
- **Stockfish 风格 NNUE** 作为 fallback(简单快速,容易被棋力测试验证)

---

## 5. 优先级建议(我的判断)

如果只能做一件事 → **重训 NN**(棋力天花板由模型决定,搜索只是放大器)。

如果再做两件 → **TT 加 score + history heuristic**(代码改动小,棋力立刻 +100-200 Elo)。

如果还有精力 → **Mobility + king safety 评估**(这两项加起来对残局/中盘都有质变)。
